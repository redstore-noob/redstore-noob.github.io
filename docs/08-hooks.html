钩子

启动钩子与下载任务钩子：不只是事后通知，还能参与决策、改写参数、拦截启动。

钩子与事件的区别：事件是事后通知（改不了任何事），钩子能参与决策。 钩子接口在 Mofumofu.ExtensionAPI.Actions，插件实现 ILaunchAction / IDownloadAction 后，宿主自动发现并调用——不需要在任何地方注册。

0. 宿主策略（写钩子前必读）#

  • 钩子全部在 UI 线程回调
  • LaunchingAsync 单个钩子 5 秒超时，超时按"放行"处理并记日志
  • 钩子抛异常按"不作为"处理并记日志——单个坏插件不会拦死其他人的启动
  • 多个插件按加载顺序依次调用，先到先改

1. 启动钩子：ILaunchAction#

ILaunchContext 一览：InstanceId / VersionId / GameDirectory 只读；JvmArguments 可变列表（唯一可写面）；Cancel(reason) 拦截。

钩子 vs 事件怎么选

场景用哪个
统计游玩时长、启动时自动开始 ping 服务器IGameLaunch 的 事件（GameLaunched / GameExited，事后通知）
拦截启动、改启动参数ILaunchAction.LaunchingAsync 钩子（能参与决策）
游戏退出后自动备份存档事件即可

判断口诀：需要改变结果 → 钩子；只需要知道结果 → 事件。

2. 下载任务钩子：IDownloadAction#

任务有 4 位数字编号（0001~9999，下载页任务卡标题前的 #0007 就是它）。 编号会话内唯一、任务结束后回收复用——不要长期缓存。

3. 权限与提醒#

  • IDownloadAction 的通知与查询要 networkReadonly；取消 / 暂停要 network
  • ILaunchAction 本身不需要权限，但注意：你的钩子会影响所有玩家的启动流程——前置检查逻辑务必保守，拿不准就放行
  • 钩子异常宿主会兜住，但这不是写坏代码的理由喵
